## Most likely to fail, and why

1. `enables_saves_and_clears_the_custom_ui_fallback_font`
   - Hypothesis: clicking a read-only picker field neither opens the list nor takes the keyboard. The test types nothing while the field is off, because the keys would go to the search field. A click while it is off only checks that the first suggestion is not drawn.
   - It depends on the Appearance page scrolling both the checkbox and the fallback picker into view (`bring_into_view` twice).
   - If Escape reaches the dialog while the list is already closed, it cancels Settings. The test presses Escape only right after typing, when `typed()` has opened the list.
2. `keeps_object_settings_stable_when_child_keys_are_staged`
   - Hypothesis: `settings-reset` drops the edits the test staged directly on the model under page `general.httpProxy`.
   - Hypothesis: the radio and host field then stage child keys or the whole `proxy` object. Both forms are read through `staged_value("proxy")`.
3. `finds_the_maven_active_profiles_setting` / `finds_the_maven_toolchains_setting`
   - They pass only if no page matches "Active profiles" or "Toolchains". The Maven page does not register these labels for the search: its keywords lack them (`builtin_pages/build.rs:257-277`) and `set_page_labels` is not called for it. So `query_changed` (`dialog.rs:343-360`) keeps Maven only when nothing else matches.
   - I grepped the page specs, the language page labels and the action titles and found no match. Plugin pages or new action titles could match, though, and the selection would move.
   - Nor is the Maven page's own control marked by the search natively, unlike the webview's highlight. If the integrator wants that, `custom_controls.rs:224` would need a `set_page_labels(build_maven::PAGE, …)` call; these tests do not check it.
4. `round_trips_spaces_quotes_and_empty_values_in_the_cmake_and_build_arguments`
   - It relies on the TOML layer storing an empty-string argument and `C:\some path\file` unchanged through `settings::set` and a re-read.
   - It relies on OK closing the dialog synchronously once the write is done.
   - I checked `quote_arg`/`parse_args` (`platform/command_line.rs:15-119`) by hand: `''`, `'it'\''s'` and `'C:\some path\file'` read back as the original words.
