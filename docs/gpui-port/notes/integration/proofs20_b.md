## Behaviour that differs from the webview, with the expected failure and its fix

- **RemoteBranchDialog.** The webview cleans the field as you type (`cleanUpBranchNameOnTyping`: a space becomes `-`). Native `ask_remote_branch_name` in `workbench/github_part2.rs` builds its prompt with `FieldRule::NonEmpty`, and `push_head` applies `clean_up_branch_name` after OK, which turns a space into `_`.
  - What fails: the field assertion (`"my feature"` ≠ `"my-feature"`). Without that assertion, the branch would be pushed as `my_feature`.
  - Fix: give that prompt a field that cleans with `crate::platform::git_ref_name::clean_up_branch_name_on_typing` as it is typed. This is the behaviour `FieldRule::Branch` already has. Either add a `FieldRule` variant that only cleans, or reuse the branch rule without its existence checks.
- **The Project view does not show attached roots** (see `ipc:workspace_attach` below).
