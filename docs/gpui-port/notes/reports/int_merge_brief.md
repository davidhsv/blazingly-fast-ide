## What a right resolution is

- Upstream's behaviour comes in whole: every upstream change stays unless a fork commit deliberately does something else in the same lines.
- Every fork feature and fix keeps working: for each conflicted file read the fork commits that touched it (their messages say what they are for) and keep their effect on top of upstream's new code. The fork's names for the modes (Blaze, Deep) stay where the fork put them; where upstream renamed or restructured what a fork commit touched, carry the fork's intent onto the new structure, do not paste old code over new.
- This branch's own changes under `crates/` keep their effect and their tests.
- `src/bindings.ts` is generated: do not hand-merge it. Resolve the Rust side, then regenerate it the way the repository does (read `CLAUDE.md` and the `export_bindings` test in `src-tauri`; `cargo test -p openidea export_bindings` writes it) and check the result has no markers.
- The locale catalogs (`src/platform/locales/text/en.json`, `zh.json`): keep both sides' keys; the files must stay valid JSON in the order the repository's tooling expects (read how they are generated or sorted: a script under `scripts/` or a package script).
- `crates/ide-host/tests/target_lsp.rs` was deleted upstream and changed by the fork: read why upstream deleted it (`git log --diff-filter=D -1 v0.1.46 -- crates/ide-host/tests/target_lsp.rs`) and where its tests went; carry the fork's change to the new place if it still applies, and say whether the file should end deleted (the manager runs the `git rm`).
- No conflict marker is left anywhere: `grep -rn '^<<<<<<< \|^>>>>>>> \|^=======$' --include='*.rs' --include='*.ts' --include='*.tsx' --include='*.json' --include='*.toml' --include='*.md' . --exclude-dir=node_modules --exclude-dir=target` over the conflicted paths prints nothing.
- Write down every resolution as you make it: file, what each side did, what you kept and why (`$S/dmerge/resolutions.md`). Where you are not sure a fork behaviour survives, say so plainly: that list is what the owner will review.
