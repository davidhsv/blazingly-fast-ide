## Points to settle by measurement, not by the notes

- Nothing ticks while the app is idle. The change bars are asked again when the repository's state changes and after an edit's pause; say exactly which timers and subscriptions each open editor adds, and prove by test that with no edit and no repository change no backend call is made over a stretch of test time (advance the clock; count the calls). An editor that is closed or hidden behind another tab asks nothing. This matters for the idle CPU measurement that comes after parity.
- Cost: nothing reads a file, asks the backend or walks the whole document, the hunk list or the bookmark list in paint; say per frame what each new thing iterates. A stale answer (the document changed, the tab closed, another file) is dropped: test it with the answer held back. Say what happens for a 5 MB file and a file with 10,000 hunks (measured once, with generated files in the temp folder), and follow the webview's limits if it has any.
- Bookmarks that follow edits are stored again: read what the webview stores and when (on every edit, on save, debounced?) and do the same; a bookmark is never lost or duplicated by an edit, an undo, a reload from disk or closing the tab without saving (tests for each: the stored line after the tab is closed and opened again is what the webview would store).
- Rollback from the popup changes the document: it goes through the same path as the existing rollback action (one undo step, the tab dirty, the same result as `vcs.rollbackLines` on that change). Assert the undo.
- Click targets (the notes' table): every existing gutter behaviour keeps its tests green without loosening them: a plain press on the numbers still sets and clears a breakpoint, fold chevrons still fold, the blame column's press, the HTTP and Spring marks, plugins' icons. The first 3 px of the chevrons opening the popup on a marked row: check that against the webview's hit area before keeping it.
- The two existing tests that pin the text's left edge (`proofs15_folding::the_fold_column_is_drawn_only_while_show_code_folding_outline_is_on`, `editor_extras::tests::distraction_free_mode_hides_the_tabs_and_the_gutter_and_centres_the_text`) get the webview's widths; say the numbers and where in the webview each comes from. Then find every other test or view that assumes where the text starts (popups placed at the caret, the completion list, inline hints, the diff sides, the minimap or overview lane) and run them.
- Icons are drawn for the active editor only, by the writer's word. The webview draws them in every editor. Close this if it is small (the icons of every visible tab editor, split panes included, with a test on a split window); otherwise the two contribution rows stay partial and you say what it takes.
- Editors that must not get these columns: the Find in Files and Bookmarks previews, the diff sides, the Paste from History preview, notebook cells, commit message and other embedded editors. Read which extensions the webview's embedded editors install and assert for each native one that its gutter is unchanged.
- A gutter launch with nothing to run shows the webview's own message (notes (e), point 7): fix it as the notes say and test the text.
- The numbers' colour token, the gutter's hairline and background (the notes' last section): fix only what the webview's CSS shows as a measured difference, with the token names.
