**One test failed before it was fixed:** `workbench::project_view_actions::tests::proofs20_tree::undo_in_the_project_view_takes_back_its_last_move_and_rename`.

- It failed in an earlier attempt at these gates: the first 20-run loop failed it in runs 3, 4, 5 and 8, and that earlier full-suite run also failed it once.
- The message was "the row to be selected did not happen within thirty seconds". The backtrace points at `proofs20_tree.rs:95`, the `select_in_tree` call after the rename.
- Cause: after a move, a rename or an undo, the Project view selects the moved file on its own (`operations.rs:697-705`). When the test selected another row before that happened, the view's selection replaced the test's.
- It never failed in 25 runs of the test alone, and failed about 4 runs in 10 when the 27 tests ran together.
- Fix: the test now waits for the view's own selection of the moved file before selecting anything (a new helper, `wait_selected_by_the_view`). After the fix: 10 out of 10 runs, then both gates above.

### 4. Safety checks

- **Proxy and the database test.** It does not leave the machine as things stand, but an environment proxy could have caught it.
  - The ClickHouse client is built with the IDE's proxy, and the default "Auto" mode uses the environment's proxy (`ide-http/src/client.rs:13-14`). That proxy does not exempt `127.0.0.1`, because hyper-util's matcher has no loopback rule.
  - macOS system proxies are not read: hyper-util is built without the system-proxy feature (checked with `cargo tree`). The IDE's own manual proxy does exempt loopback (`proxy_settings.rs:137`).
  - No proxy variable was set in this environment (`env | grep -i proxy` printed nothing). Nothing in the test process sets one: the only `set_var` calls, in `ide-host/src/shell_env.rs`, set PATH in the app and the whole login environment only in the remote server.
  - I kept the test declared and added an assertion that runs before anything connects: the test fails if any of `http_proxy`, `https_proxy`, `all_proxy` (either case) is set, so the made-up password cannot reach a proxy. If you prefer, removing the one `mod proofs20_database;` line takes it out.
- **Keychain.** "Save password" stays off, and the test asserts it. With save off, `remember` only deletes the key from the saved store, and an isolated test home keeps saved passwords in files (`backend.rs:189-191`, with the existing guard `saved_passwords_stay_in_files_under_a_temporary_home`).
- **Real Python.** The debugger fixtures run the fake adapter with `python3` from the search path, as the existing debug suite already does. The two Python tests reach it through the venv stand-in's `-m` branch.
- **Not launched:** the app binary, `gh`, Maven, Gradle or a JVM. The build test uses the build tools' stand-in Maven in its temp folder.
