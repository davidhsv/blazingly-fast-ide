## The three slices

1. `I-ACTIONS-ENABLED`: the webview's actions have an `enabled(ctx, arg)` predicate beside `when` (an action can be shown and disabled), an `indicatesRunning` flag, and batched registration; the native registry (`app-gpui/src/platform/actions.rs`) has none. Read the webview's `src/platform/actions.ts` and its spec, every action that uses `enabled` or `indicatesRunning` (list them with `file:line` and what each predicate reads), and every place the webview shows an action (menus, context menus, toolbar buttons, Find Action, Search Everywhere, the keymap page, key dispatch): what a disabled action looks like and does in each (greyed row, no key dispatch, tooltip?). Read the native registry, the generated manifest (`app-gpui/assets/gen/actions.json` and `docs/gpui-port/gen-data.mjs`: what of an action is generated and what is hand-written natively), the dispatcher (`app-gpui/src/platform/dispatcher.rs`) and every native surface that lists actions. Design: where the predicate lives natively (a predicate cannot be generated: it is code), how the 34-odd predicates are written and kept next to their handlers, how each surface asks it and how often (no predicate runs on every frame for every action: say when they are evaluated and what invalidates the answer), how `when` and `enabled` combine in key dispatch exactly as the webview's do, and the tests (the spec's cases by name plus one test per surface).
2. `I-UNTITLED`: untitled buffers (File › New Untitled; the VS Code presets bind Cmd/Ctrl+N to `file.newUntitled`). Read the webview's untitled documents end to end (creation, the tab's title and numbering, language detection on typing or paste, Save and Save As, closing with unsaved text, session restore, what the backend knows of them: `git grep -n -i untitled HEAD -- src crates src-tauri`), and the native documents, tabs, close guard, session and Save All code (`app-gpui/src/workbench/` and the editor model: find them). Design: how a document without a path exists natively (the backend's documents: does `crates/` already support one, with which calls?), every place native code assumes a document has a path (list them by grep with `file:line`: these are the hunks), what Save All, Quit, close and session restore do with one (data is at stake: say for each what is kept and what is asked), and the tests.
3. `I-TW-CONTENT-TABS`: content tabs inside a tool window (closable, pinnable, a tab menu) on the shared header, which the Run, Debug, Find, Hierarchy and Services windows use in the webview. Read the webview's tool window header and content tabs (`src/workbench/toolwindows/`), which windows use them and how (pin, close, close others, reuse of an unpinned tab, the tab menu's entries, overflow), and the native tool window header and what each of those native windows does today instead (a row of its own, a single content). A second visual slice already queued gives the native header a content slot (`docs/gpui-port/notes/reports/int_visual2_brief.md`, item 2): design on top of that slot. Design: the shared native component, its state per window and what of it is stored, how each window adopts it (one short section per window with what changes), and the tests.
