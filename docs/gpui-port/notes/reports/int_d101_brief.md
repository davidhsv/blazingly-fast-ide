## Part A: visual and behaviour defects seen in the real window

1. **A tooltip covers the popup its target opened** (shot `2026-11-14-d/03-project-widget.png`): after a click on the title bar's project widget, the widget's tooltip (the project path) is drawn over the popup and hides its first rows. A tooltip goes away when its target is pressed and does not come back while the popup that press opened is open. Fix it in the shared tooltip (`app-gpui/src/ui/tooltip.rs`, `WithTooltip`) so every target gets it; test: hover a target until its tooltip shows, click, the tooltip is gone and the popup's first row is visible.
2. **Settings rows overflow the dialog** (shots `2026-11-14-d/10-settings-font.png`, `2026-11-14-c/12-dark-plugins.png`). Measured cause for the form rows: native rows use a fixed 220 px label column (`app-gpui/src/settings_view/pages/mod.rs:54,198`); the webview's grid is `max-content minmax(0, 1fr)` per row and a hint spans both columns (`src/features/settings/components/Form.module.css:30-33`). The Plugins page's details pane overflows too (its empty state is cut at the right). Nothing of a page may be cut by the dialog at its default size; test with element bounds inside the dialog's bounds for the Font page's controls and the Plugins page's details pane.
3. **Find Action with an empty query** shows an empty list natively. Compare with the webview (Search Everywhere's Actions tab with no query) and follow it.
4. **Diff viewer**: both sides are drawn in one colour. Compare with the webview's diff viewer (does it colour syntax?) and follow it.
5. **Database tool window toolbar**: the "Filter objects" field touches the pane's right edge. Compare.
6. **Terminal**: the prompt starts at the panel's left edge with no inset, and a glyph the font lacks is drawn as a boxed question mark. Compare with the webview's terminal padding and font family list (`src/features/terminal/`), and follow both.
7. **`toolwindow.focusEditor`** answered "Action unavailable" with the Project view focused and an editor open. The webview's condition is `toolWindowFocus && !popupOpen` (`src/workbench/toolwindows/actions.ts:211-215`). Find out whether `toolWindowFocus` is on when the Project view has the focus in the native app (a test that focuses the Project view through the app and reads the key on, then off in the editor), and fix what is wrong.
8. **The interface font setting is never applied**: `appearance_runtime.rs:45` computes `font_ui` but `theme/appearance.rs` `apply` never sets `font-ui` on the theme, so a custom interface font chosen in Settings → Appearance changes nothing. Follow the webview (`src/features/settings/appearanceRuntime.ts`), with a test that sets the setting through the settings store and asserts the family the workbench root draws with. Also correct the stale header of `app-gpui/src/theme/fonts.rs` (it says JetBrains Mono is registered under a second name).
9. **The second commit button** reads "Commit an…" at the tool window's default width of 240. The native buttons use horizontal padding 12 where `src/ui/Button.module.css:10-11` has 16 and a min-width of 72; first make the shared button metrics equal to the webview's (padding, min-width, gap, font size, height: read the CSS), then compute, with the real text system if you can launch the self-check (`--self-check=<name>`: add one that prints the width of a string in the UI font at 13 px), whether "Commit and Push…" fits in the webview's layout at 240 (`src/features/vcs/CommitView.module.css`); report the arithmetic. Do not launch the Tauri app.
10. **A single-file window with no tab**: the webview shows other hints there (`src/workbench/EditorArea.tsx:19-23`). Follow it if such a window can have no tab; say so with evidence if it cannot.
